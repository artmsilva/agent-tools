pi-drydock × Apple container × Pi

The window.
Not the wall.

Davit can make an agent container observable. Apple’s runtime supplies the VM boundary. Pi’s tool-routing and policy layer must still control files, network, secrets, and export.

02 / Evidence

Strong primitive. Incomplete policy.

Why it fits

  • Each Linux container gets a lightweight VM on Apple silicon.
  • OCI images and familiar lifecycle primitives reduce custom runtime work.
  • Davit proves useful native inspection over the same XPC service as the CLI.
  • Local sandbox prior art identifies requirements without becoming a dependency.

Why it is not done

  • macOS 26 and Apple silicon constrain availability.
  • Writable mounts still carry host authority through the VM.
  • Internal networking is not domain egress policy or complete host isolation.
  • Apple’s APIs are young; Davit pins client and daemon releases in lockstep.

04 / Threat model

Controls before convenience

Filesystem

No host HOME. Copy source in, export a reviewed patch. Never mount shared git metadata by default.

Network

No egress first. Later: exact host + port broker, private-range denial, DNS-rebinding checks, audit trail.

Secrets

Host Pi makes model calls. Guest gets no provider auth and no wholesale environment forwarding.

Process

Non-root, read-only root, tmpfs HOME, dropped capabilities, pinned image, hard resource and time limits.

Tool surface

Only reviewed, sandbox-aware tools. Overriding Pi built-ins does not constrain arbitrary custom extensions.

05 / Sequence

Prove one narrow path

01

Bash spike

Pinned image, copied source, no secrets, no internet, patch export.

02

Five checks

Edit guest copy; deny HOME and network; preserve host source; apply exported patch.

03

Tool parity

Add file operations, reviewed skills, then brokered egress only after the boundary holds.

04 / Optional

Davit UI

Use for human visibility and stop controls. Keep it outside the trusted computing base.

06 / Decision

Proceed as a spike

Davit is useful because it shows the sandbox. It is not what makes it safe.

Build pi-drydock as an independent Apple-container package with its own threat model and tests. Start with copied source and bash. Do not couple it to Gondolin, run all of Pi in the guest, mount host HOME, forward credentials, or promise production hardening before the boundary checks pass.
