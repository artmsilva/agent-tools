# Apple `container` boundary spike — 2026-07-26

## Question

Can `pi-drydock` run an unprivileged task in an Apple container without mounting the host workspace, block external egress, preserve the original source, and return an applicable patch?

## Environment

- macOS 26.5.2 (`arm64`)
- Apple `container` 1.1.0, signed and notarized installer
- Recommended Kata 3.28.0 kernel
- Alpine 3.23 image index pinned to `sha256:fd791d74b68913cbb027c6546007b3f0d3bc45125f797758156952bc2d6daf40`

## Result

**Passed.** Run [`../scripts/spike.sh`](../scripts/spike.sh) to reproduce.

| Boundary check | Result |
|---|---|
| Guest process runs as UID/GID 65534 | Pass |
| Host `/Users` tree is absent | Pass |
| Root filesystem rejects writes, including UID 0 | Pass |
| Workspace and `/tmp` are writable tmpfs mounts | Pass |
| Task has empty effective/inheritable/ambient capabilities and `NoNewPrivs: 1` | Pass |
| Task cannot restore `eth0` after bootstrap brings it down | Pass |
| Host gateway listener is unreachable | Pass |
| Direct request to `1.1.1.1` fails | Pass |
| Original host source hash remains unchanged | Pass |
| Exported unified patch applies to a host-side copy | Pass |

Exported patch:

```diff
--- message.txt
+++ message.txt
@@ -1 +1 @@
-status=original
+status=edited-in-guest
```

## Findings

1. **Apple issue #1320 reproduces.** On an unmodified internal network, the guest reached a disposable host HTTP listener through `192.168.128.1`. `--internal --no-dns` alone is not a safe agent boundary. [Issue #1320](https://github.com/apple/container/issues/1320)
2. **Link-down is an enforceable no-network mode for this task model.** Bootstrap receives only `CAP_NET_ADMIN`, `CAP_SETUID`, and `CAP_SETGID`, records the gateway, brings `eth0` down, then changes to UID/GID 65534. Every task command runs through `setpriv --nnp` with empty inheritable and ambient capabilities; it cannot restore the link. Both host-gateway and external-IP probes then fail with `Network unreachable`.
3. **Copy-in must target the live mount.** `container copy` reported success but wrote beneath the running tmpfs mount, so the guest could not see the file. Streaming through `container exec --interactive` reached the live tmpfs. Export uses the inverse exec stream.
4. **No live host mount is required.** The source file was streamed in, edited only in guest tmpfs, and returned as a patch. The host original retained the same SHA-256.
5. **The result remains scoped.** It validates no-network execution for unprivileged commands delivered only through Drydock. It does not validate approved egress, arbitrary root tools, kernel escape resistance, or every host service configuration.

## Decision

`DrydockController` uses exec streams for copy-in/export, not `container copy` or a read-write host bind mount. Keep the image pinned, bootstrap network shutdown before dropping identity, wrap every task in `setpriv --nnp`, and preserve both host-gateway and external-egress regression checks.

The experimental `drydock_bash` tool now exercises that controller. It does **not** override Pi's host tools, support approved egress, export binary patches, or exercise Davit.
